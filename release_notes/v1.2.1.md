# Recify v1.2.1 Release Notes

Status: release candidate
Audience: development / release management
Target release date: 2026-07-19
Last updated: 2026-07-19

## 概要

v1.2.1は、新しい利用者向け機能を追加せず、v1.2.0で公開済みの金額編集、画面通知、認証、機密情報保護の契約を回復するpatch releaseです。

主な変更は、税抜レシート編集時の即時計算と保存結果の整合、flashとリアルタイムtoastの共通表示契約、HTMLサニタイザーのセキュリティ更新、ActionCableログの秘匿強化です。Review判定やgenerated receipt検証にも、利用者向け挙動を変えない内部整理を行いました。

破壊的変更、DB migration、必須設定変更、保存済みデータの自動補正はありません。

## Security

- HTMLサニタイザー関連の依存ライブラリを更新
  - `loofah` 2.25.2
  - `rails-html-sanitizer` 1.7.1
- ActionCableの通常ログとエラーログから、署名付きstream識別子、検証済みstream識別子、配信内容を秘匿
- parameter filteringとSentryのerror / transaction eventで、署名付きstream名を機密値として処理
- 正常なsubscribe、不正な署名の拒否、Turbo Stream配信の既存挙動を維持
- channel認証・認可、AuditLog、SecurityEventの形式は変更なし

## レシート金額編集の整合性

- 保存済みのtax-excluded、tax-included、mixedの計算basisを編集フォームへ維持
- 税額が0円へ丸められる小額税率groupがあっても、保存済みbasisを別のbasisへ反転させない
- 個数単位の明細では、明示された単価と数量を計算元とし、古いhidden明細金額を再利用しない
- 重量・容量など、明示総額を正本とする既存契約は維持
- JavaScriptの即時計算とサーバー計算を、税率group単位の丸めへ統一
- 入力されたsource値と保存用の派生値を分離し、保存失敗時の再表示へ派生値を戻さない
- 422再表示後も元の単価、数量、明細金額、割引率を保持
- 数量を往復して保存しても、保存回数により小計・税額・合計やsource basisが変化しない
- 0.5%、1%、1.1%などの小数割引率を百分率入力として正規化し、100%を超える値を拒否
- 値引き、支払調整、複数税率、小数数量、明細追加・削除の既存契約を維持

## Flash / toast通知

- flashとリアルタイムtoastを同じ表示枠へ統合し、合計最大5件の既存契約を回復
- 古い通知を上、新しい通知を下へ表示
- 自動終了または手動終了した通知の後を、残った通知が上へ詰める
- 通知ごとの表示時間と自動終了なしの指定を独立して管理
- 同じ通知を複数回closeしても例外を発生させない
- 上限超過時は、現在の契約どおり自動終了の有無を問わずDOM上で最も古い通知から除去
- Turbo cache前に表示中の通知を除去し、復帰時の重複・復活・timer二重登録を防止
- desktop、390px幅、light / dark、既存ARIA roleの表示を維持

自動終了しない通知を上限超過時に優先保護するpolicy、最大保持数の設定、priority、通知履歴、server-managed notificationは本版に含めません。これらは新しい利用可能能力となるため、v1.3.0以降の設計対象です。

## Review判定と内部品質

- blocking reasonをcontext依存warning一覧へ重複登録していた内部定義を整理
- reason、severity、needs_review、receipt status、利用者向け表示、AI出力許可集合、保存可否、auto-complete可否は変更なし
- 新しいreason、severity、statusは追加なし
- generated receipt JSON Schemaをruntime validatorへ同期
  - `tax_included`
  - `tax_excluded`
  - `mixed`
- receiptとnon-receiptで異なる必須項目をschemaへ反映
- generated receipt 112件の既存fixture内容は変更なし

## 認証・system specの安定性

- logout確認画面を、実際に操作可能なopen状態まで待つようsystem specを同期
- logout、cancel、Turbo遷移、確認前のsession維持を固定
- passkey再認証specの有効期限境界を、実際の判定時刻へ固定
- 本人確認system specのconsole確認を、実ブラウザで発生する非同期eventへ同期
- 認証、session、passkey、TOTPのproduction contractは変更なし

## Compatibility

- v1.2.0の公開互換性契約を維持
- 新しい利用者・管理者・運用者向け機能なし
- route、公開入出力形式、Active Job class名の変更なし
- DB migrationとschema変更なし
- 必須環境変数と設定変更なし
- 破壊的変更なし

## Deployment notes

- 通常のbundle install、asset build、application restartを含む標準デプロイ手順で適用可能
- DB migration、backfill、一括更新、管理者による事前設定は不要
- web processを再起動し、ActionCableログ秘匿initializerと更新済み依存関係を反映する
- 本番データを対象にした自動監査・自動修復は実行しない

## Rollback notes

- DB schema変更がないため、通常のapplication rollbackが可能
- rollbackで保存済みデータを変更または復元する処理はない
- rollbackすると、HTMLサニタイザーとログ秘匿のセキュリティ修正、Amount編集と通知の修正も失われるため、可能な場合は前進修正を優先する
- 旧版で編集済みの金額データは、application rollbackでは元の値へ戻らない

## 既存データへの影響

- v1.2.1は今後の編集時にsource basisと派生値の整合を維持
- 過去の編集で金額が変化したデータを自動判定・自動修復しない
- 本番Amount候補の件数調査は、本リリースとは別の読み取り専用運用作業として扱う
- 復旧候補はanalysis run等の保存済み根拠と現在値を比較し、金銭データを推測で上書きせず手動確認する
- 本リリース準備では本番データ監査を実施していないため、候補件数は未確定
