# Recify v1.2.0 Release Notes

Status: released
Audience: development / release management
Release date: 2026-07-15
Last updated: 2026-07-18

## 概要

v1.2.0 は、v1.1.0 までのレシート解析、金額計算、編集保存、認証、管理操作の契約を維持しながら、Railsアプリケーション全体の責務配置と依存方向を整理した品質・保守性改善リリースです。

レシートの参照、入力、アップロード、編集、解析処理を明確な境界へ分け、大規模な配置変更後も既存挙動を維持できるようarchitecture spec、offline replay、実ブラウザ回帰、security / fault-injection specを強化しました。

構造変更後の追加監査では、認証、セッション、並行処理、cleanup、storage、管理操作、UIに残っていた既存問題も修正しています。

## アプリケーション構造の改善

- 再利用可能な参照処理をQuery層へ移し、管理画面とレシート一覧・検索・集計のread責務を明確化
- ユーザー入力の正規化、厳格な数値解析、編集・手動登録入力をForm層へ分離
- 外部サービス状態などの表示整形をPresenterへ分離
- レシートworkflowをUploads、Editing、Processingへ整理
- OCR、AI、Analysis、Amount、Storageは専門境界として維持
- 管理画面の参照処理と更新処理を分離し、監査対象の更新操作をOperations境界へ集約
- Processingと解析runの循環依存を解消し、status、stage、retry、terminal transitionの所有者を明確化
- 一時的なcompatibility APIとlegacy exceptionをcaller移行後に削除
- ActiveJob class名、route、公開workflow contractの互換性を維持
- Packwerk、Rails Engine、外部operation frameworkを導入せず、Rails標準autoload構成を維持

## レシート処理workflowと回帰保護

- 単一・一括アップロード、手動作成、編集保存、解析開始を各workflow境界へ整理
- OCR、AI、finalize、run lifecycleを公開workflow経由へ統一
- 解析retryの認証・監査と、retry可否・status更新責務を分離
- stage claim、terminal status、enqueue補償、runtime config snapshotの既存契約を維持
- source evidenceの所有先を固定し、同一根拠の二重保存を防止
- BuildParams、OCR response parser、Finalize処理から独立責務を段階的に分離
- Amount Engineの公開入口と上限判定境界を統一
- Result contractをworkflow単位でimmutable化し、globalな共通frameworkは導入しない
- 外部APIを使わないoffline replayで、OCR responseから解析、金額計算、永続化、run / receipt終端までを一貫して検証
- 単一税率、複数税率、調整・支払、税詳細矛盾、source ownership、店舗名・購入日時欠損を含む代表ケースを固定
- confirmed name、OCR raw text、review reason、snapshot privacyの既存契約を維持

## 認証・セッション・アカウント保護

- 全セッション失効時にremember cookieも原子的に無効化
- アカウントロックとpasskey reset後に既存セッションを失効
- ゲストログイン時のUserSession記録を必須化し、利用中ゲストのcleanup誤削除を防止
- ゲスト本登録とguest解除を原子的に処理し、同一browser sessionでも完了通知を維持
- 認証要素の追加・変更・削除に本人再確認を要求
- 本人再確認の有効期間を高リスクな管理設定として調整可能にした
- 管理者本人確認を対象利用者とbrowser sessionへ固定
- passkey challengeの再利用、preload / navigation競合、登録上限の並行競合を防止
- recovery codeの並行再利用を防止
- アカウント復旧とログイン失敗応答から、登録・ロック状態を推測しにくくした

## Storage・quota・cleanup・retention

- storage容量予約を直列化し、並行uploadで上限を超える競合を防止
- 添付ダウンロードへ専用rate limitを追加
- 添付削除ジョブ失敗時の同期fallbackを追加
- レシート画像と解析artifactの削除・監査順序を整理
- missing storageや画像decode失敗時も内部情報を露出しないfallbackを追加
- guest、解析run、問い合わせ、SecurityEvent、UserSessionのcleanup対象を実行直前に再検査
- stale / retention cleanupでrow lock後の最新status・期限を確認
- cleanupのdry-run / execute、成功・部分失敗、AuditLog action / outcomeを整合
- SecurityEvent集約とretention cleanupの競合を防止
- 例外、検索ログ、cleanup結果から機微情報を除去

## SystemSettings・利用上限・管理操作

- SystemSettingsとユーザー別上限overrideが同じlockとinvariantを使用するよう整理
- 有効なユーザー別overrideを壊すシステム上限変更を拒否
- 並行更新でも不正な上限組み合わせを作らない契約を追加
- high-risk設定の更新・resetで本人確認、理由、確認操作、依存validation、AuditLogを維持
- validation failure時の入力値と保存済み設定を保持
- 解析run cleanup、retry、finalize retry、raw artifact取得を実ブラウザ相当で検証
- 管理操作と監査記録のtransaction整合を強化

## IP制限・security monitoring

- scanner pathへの継続的なprobeを段階的な一時IP制限へ移行
- 短時間の重複検知、query部分だけの誤検知、不正な制限昇格を防止
- 手動IP制限の重複操作と監査記録を直列化
- restriction解除時にcache reset失敗を成功扱いにしない
- scanner監査記録へ保持期限を適用
- OCR polling先を設定済みoriginへ固定
- 公開お知らせの外部リンクをHTTPSへ限定

## UI / UX改善

- 未変更avatarを設定保存時に再取得・再検証せず、storage欠損が無関係な保存を妨げないよう修正
- 設定保存失敗時に正しいHTTP statusを返し、theme / radio / indicatorを直前値へ復元
- メールアドレスのnative selection copyへ改行が混入する問題を修正
- avatar、レシート、お知らせ画像の読込失敗時に安全なfallbackを表示
- broken image iconを隠し、失敗時のpreview / download操作を無効化
- 処理ステップのcompleted、active、pending表示を区別
- 実進捗率と誤認させないindeterminate animationへ変更し、animation周期境界の巻き戻りを解消
- 複数カードの処理進捗を切り替えた後も、再読み込み時に直前のpopoverだけを復元
- reduced motion、light / dark、390px以下の表示を維持
- 本人確認要求をinfo、期限切れをwarning、認証失敗をerrorとして通知
- toastのARIA role、Turbo cache復帰、containerごとの最大表示件数を整理
- passkeyとTOTPの本人確認導線・通知を統一
- security画面の重複表示を局所partialへ共通化

## CI・architecture boundary・security tests

- service namespace、root service、公開workflow API、status writerを自動検査
- AST解析によりcomments / stringの誤検知を避けながら、private implementationへの不正な直接参照を検出
- Query / FormのDB write、enqueue、provider呼び出しを禁止
- dynamic dispatchによる重要境界の迂回を検査
- architecture scanをapp、config、lib、ERB、Rake sourceまで拡張
- legacy exceptionとbroad namespace allowlistを解消
- offline pipeline replay、guest confirmation、管理画面high-risk操作の実ブラウザ回帰を追加
- session、passkey、recovery code、quota、retention、cleanup、監査のrace / fault-injection specを強化
- fresh CIでTailwind CSSを明示buildし、生成物が空でないことを確認
- CIでduplicate file、Zeitwerk、generated receipts、RSpec / system spec、RuboCop、JavaScript / CSS lint、security scannerを実行
- develop pushでもrelease対象SHAを再検証できるようCI triggerを拡張
- WebSocket runtime dependencyを既知のsecurity advisoryへ対応した0.8.2へ更新

## Compatibility / deployment notes

- DB migrationとschema変更なし
- 新しいdirect Ruby / JavaScript dependencyの追加なし
- ActiveJob class名を維持
- 外部OCR / AI APIを使わず、保存済みfixtureとstubで回帰確認
- v1.1.0のAmount、OCR / AI fallback、edit-save、status、security contractを維持
- 構造移行前後の比較監査で新規regressionは確認されていない
