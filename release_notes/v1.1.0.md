# Recify v1.1.0 Release Notes

Status: draft
Audience: development / release management
Last updated: 2026-07-06

## 概要

v1.1.0 は大型機能追加ではなく、OCR/AI品質改善、Amount Engineの安全性強化、Service Layer境界整理、レビュー理由から修正箇所へ辿るUX改善、セキュリティ回帰防止を中心にした品質改善リリース。

特に以下を重視した。

- OCR/AIの失敗時に安全に review_needed / fallback へ倒す契約をspecで固定
- review reason の許可コードを同期し、未知コードを保存・表示・判定へ混入させない
- Amount Engineの purchase_total / final_payment_total / tax / adjustment / payment 境界を強化
- 税抜/税込/非課税/複数税率/支払調整が混在する実レシート系ケースの計算精度を改善
- Service Layerの直接依存、provider gate、Usage制限、国コード、sanitizerを整理
- クライアント改ざん前提で item-level review state の保護を強化
- UI上のレビュー確認リンク、画像プレビュー、メール表示、コピー導線を改善

## OCR改善

- `Ocr::ResponseParser` の購入日時fallbackを改善
  - Azure structured date/time がない場合、近接する日付行と時刻行を結合
  - 曜日や軽い空白混入を低リスク範囲で吸収
  - 遠い時刻行や過剰推測は対象外
- OCR parserで支払時割引を adjustment candidate として抽出
  - 支払時割引、決済割引、キャッシュレス割引など明確なsigned amountのみ対象
  - 支払方法、お預かり、お釣りは除外
- OCR parserでポイント利用を payment adjustment candidate として抽出
  - ポイント利用、ポイント支払、point usageを候補化
  - ポイント付与、獲得予定ポイント、保有ポイント、利用可能ポイントは除外
- 支払方法誤認を抑制
  - お預かり、お釣り、change、ポイント、クーポン、支払時割引、キャッシュレス還元を支払方法として拾わない
  - クレジット、現金、電子マネー、QR決済など明確な支払方法は維持
- レシート解析profileへ国・地域依存パターンを寄せる整理を実施
  - 日本向けprofileに寄せるべきOCRパターンを整理
  - 店舗特化判定は削除方針
- 店舗名の大文字小文字復元を改善
  - OCR正規化で小文字化された店舗名について、AIへ渡す判断材料を補強
  - 固定値はSystemSettingsで調整可能にした

## AI改善

- `review_reason` 許可コードを同期
  - `PromptTemplate`
  - `Ai::ResponseParser`
  - `ReviewReasons`
  - docs上の定義
- AI response parserで未知の review reason を安全に除外
- adjustment系 review reason も同じ許可コードルールで扱う
- AI deterministic guardを強化
  - name completion OFF時はOCR item名を勝手に変更しない
  - item index / adjustment source line / source text / amount evidence の検証を追加
  - blocking review reason があるのに `needs_review=false` の場合の補正を固定
- `Usage::LimitExceeded` をAI fallbackで握りつぶさない
  - quota超過を provider failure / fallback failure と混同しない
- Provider gateをfail-closedへ寄せた
  - 設定取得失敗時にOCR/AI provider callが有効側へ倒れないようにした
- 国コード契約を整理
  - 内部国コードは `JPN` / `USA` など3文字固定
  - `JP` aliasは廃止
  - `JPN`のみ正式対応、`USA`はunsupportedのまま

## Amount Engine改善

### 安全契約の固定

- `purchase_total` と `final_payment_total` の契約をspecで固定
  - `resolved[:total]` は購入合計
  - `computed[:final_payment_total]` は支払照合用
  - `Receipt.total_amount` へ保存するのは purchase total
- all rejected candidate contractを追加
  - `safe_to_auto_complete: false`
  - `selected_candidate_status: "rejected"`
  - `amount_engine.no_safe_candidate: true`
  - review draftとしてresolvedは残すが自動完了しない
- positive overpayment suppress条件を厳格化
  - analysis context
  - positive delta
  - single payment
  - cash / tendered / received / お預かり系に強く一致
  - exact final payment lineが併存しない
  - 非現金、複数支払、manual/edit_saveでは抑制しない
- `SystemSettings` 取得失敗時の税抜補正fallbackをfail-closedへ変更
  - `UnknownKeyError` / `ValidationError` 時はdisabled相当
- snapshot contractを強化
  - schema_version追加
  - raw OCR text / provider raw response / endpoint / source_text / description / label-like field の漏洩防止specを追加

### ReviewPolicy境界

- `payment_amount_mismatch` は最終判定でblockingになり得ることを固定
- `price_tax_inclusion_uncertain` のwarning-only例外を厳格化
  - printed tax details netと完全整合していても、competing exact basis candidateがあればreview-required
- purchase adjustment tax allocation uncertaintyをreview-required化
  - 複数税率
  - mixed basis
  - printed tax detailsあり
  - 単一positive税率 + 非課税混在
  - purchase adjustmentのtax_rate missing
- same-rate mixed searchが探索上限に達した場合、silent completedにしない
- Service boundary specでAmount Engine内部実装の直接呼び出しを検知

### Canonicalization / 支払調整

- point / cashless reward / gift card / coupon / payment discount の二重計上防止specを追加
- 同額・同種でも別source lineなら正当な別行として残す
- provenance不足時に安易にcollapseしない方針を固定
- cash tendered suppress後に tendered amount を actual payment amount と誤確定しない契約を固定

### 大規模リファクタ

- CandidateGenerator肥大化を解消するためcandidate familyへ分割
  - ReceiptInput
  - ItemAmounts
  - PrintedTaxDetails
  - MixedTaxBasis
  - IncompleteTaxDetailsReceiptTax
- `CandidateFamilyRegistry` を追加し、候補family順序を明示
- `CandidatePipeline` を追加し、候補生成・評価入口を一本化
- `EvidenceExtractor` を追加し、evidence生成を分離
- `TaxDetailEvidence` を追加し、税詳細evidence参照を集約
- `ReviewFacts` を追加し、ReviewPolicyの判定材料を構造化
- `CandidateProfileResolver` を追加し、ResultAdapterのprofile fallbackを分離
- Amount familyの不要な委譲口を削除

### 税抜/税込/非課税混在対応

- 2019年コンビニ系の税抜/税込/非課税/複数税率/支払調整混在レシートを修正
  - `mixed_by_tax_rate_group/floor` 候補を正しく選択
  - 税抜単価を税込単価へ補正
  - payment adjustment反映後の `final_payment_total` と支払額を一致
- 印字税詳細と完全一致する税抜/税込/非課税の組み合わせで、`printed_tax_details_gross` が不適切に勝たないよう調整
- 8% / 10% の各税率グループを `なし / 税込 / 税抜 / 税込税抜混在`、非課税あり/なしで組み合わせた30通りmatrix specを追加

## Service Layer改善

- Service Layer boundaryを強化
  - controller / job / model / helper / presenter / serviceからchild namespaceを直接呼ばない契約をspec化
  - parent facade経由に統一
- `Analysis::StoreNameCandidateClassifier` の直接参照をparent facade経由へ整理
- `ReceiptAnalysisPipeline::Result#success?` の誤用防止契約を追加
  - job enqueue判定は `next_step` を見る
- completed判定契約を強化
  - blocking review reason があればcompletedにしない
  - adjustment / payment / tax / detail flagsがstatus判定へ反映されることを固定
  - AI fallback / OCR-onlyはreview_needed
- upload / admin retry / pipeline開始時のprocessing遷移とerror clearing契約を固定
- admin finalize_retry validationをstrategy-aware化
  - `ocr_only` / `fail_receipt` でAI snapshotを必須にしない
  - `ai_success` / `ai_fallback` では必要snapshotを要求
- `ReceiptAnalysisRuns.record_final_result` の二重記録疑いを確認し、契約を固定

## Security改善

- client paramsの `receipt_items_attributes[][needs_review]` / `review_reasons` を信頼しないよう修正
  - hidden field改ざんでitem-level review stateを軽くできない
  - status completed偽装につながる経路を塞いだ
- strong params / protected attributesの回帰specを追加
  - `status`
  - `amount_calculation_profile`
  - `safe_to_auto_complete`
  - `selected_candidate_status`
  - top-level `review_reasons`
  - item `raw_text`
- 他人の nested attribute id を混ぜても更新・削除できないことを確認
- Sanitizerを強化
  - snapshot / admin / audit / external detail / SecurityEvent metadataで forbidden keys を落とす
  - blocked keysを共通化
- ActiveStorage画像URLのログ秘匿を強化
  - 画像表示・ダウンロード時の署名付きURLがRailsログに残るリスクを低減
- SecurityEventの誤検知を抑制
  - 通常のレシート編集で送られる明細・調整・支払いのnested `id` を `parameter_tampering_attempt` として記録しない
  - top-level protected receipt attributes や nested `receipt_id` の検知は維持
- forbidden key例
  - `access_token`
  - `refresh_token`
  - `set_cookie`
  - `subscription_key`
  - `client_secret`
  - `api_key`
  - `authorization`
  - `provider_raw_response`
  - `prompt`
  - `system_prompt`
  - `user_prompt`
  - `endpoint`
  - `operation-location`
  - `operation_location`
